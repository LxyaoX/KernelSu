# 内置能力总览

<Badge text="按需启用" type="info" /> <Badge text="多数需要重启" type="warning" /> <Badge text="设置入口" type="tip" />

“内置能力”指随 FinaSU 发布、由 `ksud` 和内核驱动提供运行支持的功能。它们不是需要单独安装的普通模块；入口集中在管理器的 **设置 → 功能**，但每项能力的依赖、生效时机和风险并不相同。

::: warning “内置能力”不等于 Built-In 安装方案

这里的“内置”描述的是功能随 FinaSU 提供。它与安装文章中的 [Built-In 内核构建方案](/guide/install/built-in/) 不是同一个概念。LKM 安装同样可以使用 YukiZygisk 与 Sui；模块挂载则由你安装的元模块负责。

:::

## 它们如何协作

这些能力不是一条线性的功能列表。模块文件怎样被看到由你安装的元模块决定，FinaSU 不再内置挂载引擎；YukiZygisk 由内核辅助向应用进程注入代码；Sui 再借助 Zygisk 提供 Shizuku API 后端。SUSFS 则取决于内核源码集成或已加载的 SUSFS-LKM。

```mermaid
flowchart TD
    K["FinaSU 内核驱动"] --> Z["YukiZygisk"]
    MM["你安装的 Metamodule"] --> NM["模块目录发布"]

    Z --> ZM["Zygisk 模块"]
    Z --> S["Sui"]
    Z -.-> X["外部兼容 Zygisk 提供者"]
    X -.-> S

    E["SUSFS 源码补丁或 LKM"] -.-> O["SUSFS 对接"]
    O -. 接管 uname .-> U
```

图中实线表示由 FinaSU 直接提供或驱动；虚线表示外部提供者。Sui 可以使用内置 YukiZygisk，也可以使用外部兼容的 Zygisk 提供者。外部提供者的实际差异是：==Sui 可以运行，但 FinaSU 无法验证其注入结果==。

## 三类能力，不要混在一起

### 用户态引擎

**YukiZygisk、Sui** 由 `ksud` 管理生命周期，配置写入 `/data/adb/ksu/`。启动阶段是否真正运行，要看本次启动记录，而不是只看开关。

- YukiZygisk 可能在启动时让位给外部 Zygisk 提供者。
- Sui 依赖可用的 Zygisk 后端，自身不是 Zygisk 提供者。
- 模块挂载由元模块自己的 `metamount.sh` 完成；没装元模块时模块不生效，管理器不再提供挂载模式。

### 内核补丁与 LKM

**SUSFS** 的实现不在此仓库。FinaSU 只提供状态检测、配置和安全对接。没有内核补丁时可以使用匹配的 SUSFS-LKM，但其功能范围通常少于源码集成版。

## 开关、配置与本次启动

:::: field-group

::: field 下次启动配置
@type `持久设置`
例如 Sui 启用意图。写入磁盘后仍然需要重新启动相关组件或设备。
:::

::: field 本次启动状态
@type `运行结果`
表示当前这次启动实际选择了哪个提供者、是否完成注入，或者驱动是否就绪。它会因外部提供者、启动保护、驱动加载失败而不同于配置。
:::

::: field 即时规则
@type `热更新`
元模块发布出来的模块目录通常可以在当前启动内更新。已有进程仍可能保留旧状态。
:::

::: field 新进程生效
@type `进程级`
:::

::::

::: important 先区分“谁提供”和“谁记住”

配置页保存的是期望状态。外部模块、启动保护、驱动不可用和上次异常退出都可能改变本次实际提供者。排查时同时查看 **配置模式**、**本次启动** 和 **错误/警告**。

:::

## 推荐启用顺序

:::: steps

1. **先确认 Root 工作正常**

   打开管理器，确认驱动已连接，并能正常执行一次受控 Root 操作。内置能力不能修复损坏的 FinaSU 驱动。

2. **一次只启用一项能力**

   先完成依赖链的底层部分：例如先确认 Zygisk 实际注入，再启用 Sui。不要同时更换元模块、Zygisk 提供者和应用策略。

3. **检查是否需要重启**

   YukiZygisk 与 Sui 通常需要重启才进入新状态。

4. **用目标应用验证**

   回到目标应用检查实际效果。Zygisk 模块和 Sui 权限都应以目标进程结果为准，而不是只看全局开关。

5. **失败时回到最小配置**

   先关闭新增能力，确认基础 Root 与启动正常，再按错误信息定位依赖。不要连续叠加开关来“试出来”。

::::

## 常见状态词

| 显示或状态 | 通常含义 | 不要误解为 |
| --- | --- | --- |
| **未启用 / Disabled** | 当前配置没有要求该能力工作 | 功能一定不可用 |
| **已配置** | 设置已经保存，但尚未生效 | 目标进程已经采用设置 |
| **正在启动 / Mounting** | 启动阶段仍在执行 | 已成功完成 |
| **已注入 / Mounted / Ready** | 当前启动通过了对应检查 | 所有应用场景都一定兼容 |
| **部分 / Partial** | 只有部分 ABI、目标或步骤成功 | 完全失败或完全成功 |
| **不可用 / Unsupported** | 当前内核缺少特性或驱动没有响应 | 管理器按钮损坏 |
| **由外部提供者接管** | 另一个模块或内核功能正在负责 | FinaSU 的配置一定被修改 |

不同功能的检查标准不同。例如 YukiZygisk 的“已注入”要求当前启动、对应 ABI、守护进程和 Zygote 进程都得到确认；Sui 的外部提供者状态则可能只能验证服务存在，不能验证完整注入链。

## 数据与诊断

```file-tree title="/data/adb/ksu 内置能力相关位置"
/data/adb/ksu
├── module_mount_boot            # 本次启动是否已跑过元模块的 metamount.sh
├── module_mount.lock            # 冷启动与 late-load 之间的互斥锁
├── yukizygisk/yzconfig.json    # YukiZygisk 设置（注入开关在页面顶部）
├── zygisk-boot.json            # 启动保护与失败计数
├── .zygisk/state.json          # 当前注入状态
├── sui/                        # Sui 状态与守护进程记录
└── folksu-susfs/               # SUSFS 对接配置与状态
```

这些文件用于诊断，不是手工配置入口。直接编辑可能绕过校验、锁和事务回滚，导致管理器显示与内核实际状态不一致。

## 排错顺序

:::: steps

1. **看依赖**

   Sui 先看 Zygisk；模块不生效先看有没有装元模块。

2. **看启动代次**

   确认页面上的“本次启动”信息属于当前启动。配置改过但未重启时，两者本来就可以不同。

3. **看保护与回退**

   YukiZygisk 在载荷未安装或内核模块过旧时不会注入；模块挂载完全依赖元模块自己的 `metamount.sh`，没装就不注入。先处理警告，不要重复触发。

4. **用目标进程验证**

   检查目标应用是否重启、ABI 是否受支持、UID 是否选对，以及是否有独立 namespace 或额外权限限制。

5. **保留日志再恢复**

   需要回退时，先记录错误文本、时间、UID/PID 和模块列表，再关闭对应能力。删除数据目录会丢失用于定位问题的证据。

::::

## 能力边界

- **内置能力不是隐身保证。** 元模块与 SUSFS 各自只处理一部分可观测面。
- **Sui 不是无条件 Root。** 应用仍要连接 Sui 并取得逐应用权限。
- **外部 Zygisk 提供者不由 FinaSU 管理。** FinaSU 可以让位并检测服务，但不会替你验证或修复外部提供者的注入链。

### 为什么开关开了，功能却没生效？

先检查依赖和本次启动状态。YukiZygisk、Sui 都需要新启动周期。

### 多个内置能力可以同时使用吗？

可以，但要保持职责不冲突。Folk Mount 与 NoMount 是互斥的挂载提供者选择；Sui 明确依赖 Zygisk。

### 需要卸载模块来关闭内置能力吗？

不需要。使用管理器中的开关或对应 `ksud` 生命周期命令。手工删除状态目录可能留下仍在运行的守护进程或与模块禁用标记不一致的状态。

### 为什么文档不推荐同时安装另一个同类提供者？

两个 Zygisk 提供者、两套挂载执行器或两个 Sui 实例会竞争同一注入点、挂载路径或 Binder 服务。FinaSU 能在部分场景主动让位，但不会替外部实现解决冲突。

{用户}
我只想运行一个 Zygisk 模块，需要先开 Sui 吗？

{助手}
不需要。Sui 只是使用 Zygisk 后端的 Shizuku API 服务，不是所有 Zygisk 模块的前置条件。

NoMount 显示 ready，是否说明模块一定已经注入？

{助手}

{用户}
SUSFS 能靠安装模块补出来吗？

{助手}
源码集成版不能。也可以加载 SUSFS-LKM 作为替代，但它受 KMI 和导出能力限制，功能通常少于源码集成版。
